# M3 semantic-analysis slice

ArchMind optionally invokes a local FOSS `clang-uml` executable against a CMake `compile_commands.json` build, reads class-diagram JSON schema v3, and merges normalized observations into the same immutable snapshot as the CMake target graph. The adapter generates its own temporary config and output, invokes arguments without a shell, has a five-minute timeout and a configurable 1–32 thread bound, and does not upload source. The compile database's SHA-256, clang-uml/LLVM versions, configuration and Git revision are snapshot metadata. The configured compiler flags, definitions, include paths and language standard come from the compilation database. Reanalysis creates a new snapshot; a failed semantic pass leaves the last complete snapshot intact.

## Graph semantics and evidence

- Nodes: `NAMESPACE`, `CLASS`, `STRUCT`, `METHOD`, plus source `FILE` nodes. Class/method stable keys use qualified names and method parameter types/constness, not clang-uml's per-diagram IDs.
- `CONTAINS` links namespace hierarchies, namespace-to-class, file-to-class and class-to-method. Source declaration lines are stored only if clang-uml reports a path and valid line inside the project root.
- `INHERITS` maps clang-uml `extension`. Its relationship object lacks an exact source line, so edge evidence has `line_start: null` and `confidence: derived`; the class declaration itself retains its reported line.
- `USES_TYPE` maps association, aggregation, composition and dependency; its subtype remains visible in the class graph. When a uniquely labelled member matches, its declaration path/line is verified evidence; otherwise the relationship line is `null`.
- Cross-namespace class relationships yield `DEPENDS_ON` namespace edges with `origin: derived` and supporting class/relationship evidence. They are not independent declarations.

The query service exposes `scope=target|namespace|symbol` on bounded `/subgraph`, target-owned classes via `/targets/{id}/symbols`, reverse bounded class impact via `/impact`, and cross-target class relationships via `/edges/{id}/symbol-trace`. Impact returns affected classes and target ownership where known. The React explorer offers a graph-level selector, target-to-class drill-down, namespace view, class impact and edge evidence. The backend, CLI and UI all use the same snapshot repository/query service.

## Current limits

This is not a full M3 gate. clang-uml class diagrams do not emit free functions or call graphs here; custom LibTooling and method-level call tracing are later work. A header omitted from CMake target sources cannot be assigned a target reliably, so target-to-symbol trace and impact target estimates can be incomplete. The adapter records that condition in diagnostics instead of guessing ownership. The compile database hash is groundwork for incremental reindexing; indexing still runs in full. Clang-uml supports local Windows use, but the real executable/fixture integration has only run on Linux; Windows CI exercises the captured schema contract, not live clang-uml. The M1 CMake File API link/cycle limitations still apply.

## Reproduce the real Linux adapter test

Install `clang-uml` 0.6.x and run `ARCHMIND_CLANG_UML=/path/to/clang-uml uv run pytest -q tests/test_m3.py`. On this Debian 13 host the tested executable was release 0.6.3 (LLVM 19.1.7). A committed JSON fixture generated by that release keeps parser and query regression tests runnable without requiring clang-uml on every developer machine.
